# 内容设计草案

## 文档状态

本文件把 Expo 中已有的功能概念转为 Lazy 的非承诺设计输入。Lazy 是一个懒狗工具箱，不考虑平衡性。它不是实现规格，名称、数值、交互、视觉和系统边界都可以在后续讨论中更改。

当前源码不得依赖本文件中的内容。只有某项设计被单独确认后，才为它建立实现、资源、数据生成和测试。

## 虚空网格维度

该内容已确认实现。`lazy:void` 是无自然地形、生物、特征和雕刻器的独立维度，默认在高度 128 生成每三区块一个周期的规则网格，使用石砖边界和平滑石内部。维度沿用主世界天空效果、昼夜与床规则，建筑高度为 -64 至 319。

`lazy:grid_generator` 通过维度 JSON 配置层高、网格区块大小、群系、边界方块和内部方块。覆盖示例和变更语义见 `docs/void-dimension.md`；已有区块不会因配置变更而重写。

## 传送器

该内容已确认实现。`lazy:teleporter` 是不可堆叠、耐火、史诗稀有度的手持物品，每件物品通过数据组件独立保存返回位置和虚空目标位置。默认蓄力一秒、成功后冷却五秒，具体传送参数由 Fzzy Config 管理并由服务器同步。

Curios 为玩家提供一个通过服务端自定义校验器、仅接受 Lazy 传送器的单格 `teleporter` 槽位。客户端提供默认未绑定的游戏内快捷键；槽位内装备传送器后，按键向服务端发送无参数激活请求并立即传送，不需要蓄力，但仍遵守与手持使用相同的成功和失败冷却。服务端拒绝跨维度切换期间和同一游戏刻内的重复快捷键请求，手持右键蓄力行为保留不变。

传送前会在目标附近搜索安全落点；外界方块永不修改，虚空端可按配置补建平台。只有跨维度切换成功后才更新位置数据与冷却。缺失维度、不安全落点和切换失败均通过本地化消息反馈，旧 `expo:*` 数据不迁移。

## 能量电池

该内容已确认实现。`lazy:energy_battery` 是不可堆叠、耐火、稀有且带附魔光效的无限能量物品。它暴露 NeoForge 物品能量能力，只允许抽取，固定显示 500,000,000 FE 的存量与容量，单次能力抽取上限同样为 500,000,000 FE。

潜行对支持方块能量能力的目标使用时，电池从点击面查询接收能力，并在服务端以 `Int.MAX_VALUE` 请求一次性传输能量，再在动作栏报告目标实际接收的数量。旧 `expo:eternal_battery` 数据不迁移。

## 能量源

该内容已确认实现。`lazy:energy_source` 是具有方块实体的金属方块，六面始终暴露只可抽取的无限能量能力，外部管线可以随时拉取，每次抽取上限为 500,000,000 FE。

主动推送默认关闭，玩家可在手持任意物品时潜行使用方块切换，并在动作栏查看结果。开启后，方块实体每个服务端 tick 向六个相邻面的接收能力各请求传输 500,000,000 FE；邻接能力通过 NeoForge 缓存跟踪。开关随世界存档保留，但破坏掉落不携带设置，重新放置恢复关闭。该内容不提供方向、红石、配置、界面或模型状态控制。

## 燃料源

旧概念是具有方块实体的金属方块，可在煤炭和煤炭块两种模式间切换。普通使用给予玩家一组当前燃料，潜行使用切换模式；后台逻辑周期性向相邻物品能力尝试插入燃料。参考周期为 640 tick。

它的定位是无限燃料工具。需要确定模式切换界面、自动化频率、方向过滤和红石控制。新的插入算法必须遵守 handler 返回的剩余物、槽位数量和模拟语义，避免意外复制物品。

## 缓冲器

该内容已确认实现。`lazy:buffer` 提供八个相互独立的物品槽，每槽容量 256；另有四个相互独立的流体罐，每罐容量 64,000 mB。物品按物品及数据组件精确匹配，流体按流体及组件精确匹配；槽或罐清空后可以绑定新的类型。

六个方向公开相同的 NeoForge 物品和流体能力，不提供方向配置、锁定或升级。普通交互打开不含玩家背包的实时界面，界面可清空全部内容；潜行交互在动作栏汇报总量。服务端方块实体是存储真相，打开菜单时发送初始快照，内容变化后只同步给正在查看该菜单的玩家。清空请求由服务端校验当前菜单和交互距离。

方块被移除时生成一个缓冲器物品，不拆分生成物品实体或流体容器；存在内容时携带完整方块实体数据并在重新放置后恢复，空缓冲器不携带方块实体数据，因此可以与全新的缓冲器堆叠。其贴图与合成配方沿用 Expo 的物品缓冲器。

## 能力与通用工具

Lazy 为能量电池注册物品能量能力，为能量源注册方块实体能量能力，并为缓冲器注册方块实体物品与流体能力。能量电池和能量源复用无状态的无限能量存储，能量源使用服务端 ticker 与六向方块能力缓存。

Lazy 可以保留与内容无关并确有复用价值的工具，但能力注册、存储实现和数据 codec 必须随具体内容设计一起进入源码，不能预先冻结旧行为。

## 界面与客户端

旧物品缓冲器界面以简易深色面板展示一个物品图标、存储数量和物品名称，并在悬停时显示标准工具提示。菜单通过额外网络数据传递模板、数量和容量。

后续界面应先确定交互目标，再选择原版容器、纯信息屏幕或 HUD。需要定义客户端注册边界、菜单有效性、无障碍和缩放、本地化、网络包大小及状态更新频率。

## 上升命令

旧概念提供 `/expo rise`，从玩家当前位置向上扫描第一个具有实体支撑、两格净空并可见天空的位置，然后把玩家移动到该位置。Lazy 中若保留，命令名应变为 `/lazy rise`。

需要重新决定命令权限、冷却、维度限制、世界边界、伤害风险、是否允许非玩家执行，以及找不到位置时的反馈。扫描必须有明确上界并避免在主线程执行无界工作。

## 玩家保护

该内容已确认实现。玩家保护通过 `/lazy protection` 命令树控制，当前提供伤害上限（damage cap）功能。

伤害上限限制玩家单次受到的伤害不超过设定阈值。阈值为 0 时等同于免疫。虚空伤害和 `/kill`（`BYPASSES_INVULNERABILITY` 标签）不受限制，始终正常生效。

功能通过 NeoForge Data Attachment 在玩家实体上持久化不可变的 `DamageCapData`（`enabled`、`threshold`），支持 `copyOnDeath` 跨死亡保留。阈值 0 的稳定免疫通过伤害容器创建前的 `EntityInvulnerabilityCheckEvent` 实现；阈值 > 0 时在最低事件优先级的 `LivingIncomingDamageEvent` 中封顶伤害值，随后护甲和附魔正常减算。两条路径均放行 `BYPASSES_INVULNERABILITY` 标签伤害。

命令树如下，权限要求 OP 2：

- `/lazy protection damage_cap` — 查看当前状态
- `/lazy protection damage_cap on` — 开启
- `/lazy protection damage_cap off` — 关闭（保留阈值设置）
- `/lazy protection damage_cap set <value>` — 设置阈值（≥0，0=免疫），不改变开关状态
- `/lazy protection damage_cap reset` — 移除全部设置，恢复未配置状态

后续可在同一 attachment 和命令树下扩展摔伤免疫、火焰免疫、溺水免疫、击退免疫、饥饿锁定等功能。

旧内容依赖方块状态、模型、物品模型、战利品表、配方、挖掘标签、维度数据以及 `en_us`、`zh_cn` 翻译。Lazy 实现任何内容时都应同时补齐相应数据生成、贴图来源记录和双语本地化。
