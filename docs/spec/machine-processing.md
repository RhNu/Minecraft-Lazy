# 机器处理规格

## 范围

本规格定义处理机器共享的资源提交规则，以及模拟室与塑形机各自不能由通用类型直接表达的不变量。具体容量、配置范围、槽位布局和资源标识由实现维护。

## 共用流水线

| 阶段 | 输入 | 提交条件 |
| --- | --- | --- |
| 预输出 | 现有输出仓 | 目标明确接受后才扣账 |
| 恢复提交 | 已持久化的待提交结果 | 所有当前可容纳部分按同一结果继续推进 |
| 生成工作 | 当前输入或活动快照 | 不存在阻塞中的待提交结果 |
| 资源事务 | 输入仓与输出仓 | 扣除和增加可以作为一个整体提交 |
| 后输出 | 本 tick 新产生的输出 | 使用同一运输预算的剩余部分 |
| 显示更新 | 最终工作状态 | 只同步渲染所需状态 |

工作预算限制产物生成，运输预算限制向外部目标发起的工作；二者不能相互放大。被动能力访问、面输出和网络输出必须观察同一输出仓。

## 状态与恢复

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 空闲 | 当前没有可推进工作 | 等待有效输入或设置 |
| 运行 | 活动作业仍可消耗工作预算 | 推进快照中的工作 |
| 阻塞 | 已生成结果暂时无法完整入仓 | 优先继续提交同一结果 |
| 故障 | 结果一致性无法确认 | 保持状态并等待明确恢复 |

活动作业与待提交结果都属于持久化状态。重载只能恢复现有工作，不能重新解析或重新随机生成已经决定的结果。

## 模拟解析上下文

模拟室采用固定的 `1 + 3` 输入模型：一个目标/种子槽定位候选，三个无序上下文槽既可放配方条件物品，也可放只提供武器或焚化行为的工具。每项条件必须由不同槽位满足；额外行为工具不影响条件匹配。上下文物品始终不消耗、不损耗，解析过程不执行放置、使用或破坏事件。

显式物品、自动适配、实体 profile 与 injection 在解析前统一为 variant 注册表项。每项具有稳定的来源类型、配方 ID、分组 ID、优先级和条件集合；目标缓存只保存候选 variant，换动三个上下文槽时仅重新执行至多三对三的匹配，不扫描物品注册表。分组用于检查、脚本和展示归类，不参与优先级比较。

| 选择阶段 | 当前约束 |
| --- | --- |
| 显式基础配方 | 工具满足时覆盖自动方案；不满足时允许自动回退 |
| 自动基础方案 | 只识别能够从结构与成熟战利品证明的目标 |
| 实体 profile | 工具不满足时使用默认实体战利品模拟 |
| injection | 叠加所有目标与工具均匹配的项 |
| 基础方案排序 | 优先级降序，再按工具条件数降序 |
| 同级结果 | 多个最高等级候选构成冲突并拒绝启动 |

炉类行为工具只处理物品产物：熔炉、高炉和烟熏炉分别查询当前已加载的熔炼、烧制和烟熏配方。每次查询以当前 `ItemStack` 的完整数量作为一个批次；匹配后按配方结果数量缩放产物，未匹配则原样交给后续处理器。同优先级的产物处理器保持三个工具槽的前后顺序，因此多个炉类工具可以连续尝试多次；活动作业仍使用启动时冻结的工具快照。

方块战利品部件独立应用外层概率和抽取次数，再用冻结的成熟 `BlockState`、工具和当前已加载战利品表产生内部结果。作业启动后，目标、工具、基础方案、注入和所有产出部件一并冻结。

实体 profile 每轮依次抽取目标战利品表、实体自定义死亡掉落与装备掉落，再调用已安装 Integration 注册的定向死亡掉落处理器。该兼容入口只复用明确注册的 partner 处理器，不向 NeoForge 事件总线广播 `LivingDropsEvent`，避免把任意第三方死亡副作用引入模拟。

每轮随机工作单元的数量由处理核心堆叠数决定；核心等级的产出倍率只在单个工作单元完成战利品抽取与物品行为处理后缩放结果数量，不增加随机抽取或产物处理次数。工作预算限制每 tick 完成的随机工作单元数。

## 随机结果

模拟室在作业开始时冻结影响本轮结果的输入：

| 快照内容 | 目的 |
| --- | --- |
| 已解析模拟来源 | 数据重载不改变进行中的作业 |
| 工具选择 | 中途换槽只影响下一轮 |
| 处理核心效果 | 进度、倍率和工作量保持一致 |
| 产出描述 | 随机抽取不重新查询配方表 |

每个随机工作单元先生成完整结果，再包装为唯一待提交结果。输出仓种类不足时允许按资源身份逐步提交，但在整份结果完成前不能生成下一份随机结果。

输出仓已有内容本身不是停止工作的理由；只有待提交结果无法推进、资源身份容量不足或数量运算无法安全完成时才形成背压。

## 无损换算

塑形机只在同一材料的已知形态之间转换。设输入单位值为 `a`、目标单位值为 `b`，最小整数交易为：

```text
g = gcd(a, b)
inputPerTrade = b / g
outputPerTrade = a / g
```

| 约束 | 含义 |
| --- | --- |
| 整数交易 | 不足一笔的输入留在输入仓 |
| 原子提交 | 同一次交易的扣输入和加输出同时成功 |
| 无余数账本 | 材料守恒完全由最小整数交易保证 |
| 固定种类扫描 | 每 tick 成本由条目上限决定，与累计数量无关 |
| 公平起点 | 扫描游标轮转，持续有工作的条目不会永久饥饿 |

交易次数受可用输入、输出容量和安全乘法共同限制。幽灵样品只选择目标形态，不参与资源事务。

## 测试边界

| 应验证 | 不固定 |
| --- | --- |
| 随机结果在阻塞与重载后不重滚 | 具体模拟配方内容 |
| 无序一对一工具匹配与同级冲突关闭 | 第三方植物注册清单 |
| 部分提交最终保持整份结果一致 | NBT 字段名称 |
| 换算守恒、整除与溢出边界 | 材料形态全集 |
| 工作预算和运输预算相互独立 | UI 槽位排列 |
