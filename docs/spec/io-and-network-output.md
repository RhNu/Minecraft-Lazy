# IO 与网络输出规格

## 范围

本规格定义统一 IO 状态、配置卡目标选择和网络 provider 的失败语义。机器只提供输出源；路由、预算、重试与目标恢复由公共 IO 层负责。

## IO 模式

| 模式     | 外部访问                       | 主动行为             |
| -------- | ------------------------------ | -------------------- |
| 被动     | 按机器 capability 契约允许抽取 | 不主动发送           |
| 面输出   | 保留 capability 访问           | 向已配置相对面发送   |
| 网络输出 | 保留 capability 访问           | 向持久化网络目标发送 |

模式互斥，但都从同一输出源扣账。物品和流体在 NeoForge capability 边界按原版数值范围分块；网络 provider 可以在自身能力范围内接受长数量。

## 调度

`OutputDispatcher` 在输出端口、资源身份、资源类型和方向之间轮转起点。一次 tick 使用固定调用预算，前置输出与后置输出共享该预算。

| 要求               | 结果                                 |
| ------------------ | ------------------------------------ |
| 公平轮转           | 单一持续阻塞目标不会永久占据起点     |
| 扣账以后端确认为准 | 部分接受只扣除实际接受量             |
| 模拟与执行分离     | 模拟阶段不能产生外部副作用           |
| 固定预算           | 资源累计数量不扩大每 tick 目标调用数 |

面输出转换以资源种类为键注册。内置资源和可选 Integration 都通过同一 factory 创建每台机器的邻接 capability 缓存；公共 dispatcher 不识别第三方 stack 或 capability 类型。

物品容器中的资源标记同样按资源种类注册提取器。提取器只读取 capability，不修改容器；容器同时暴露多种能力时，按提取器注册顺序选择第一个非空资源。

## 结果语义

| 结果                     | 路由行为                       | 持久化影响                           |
| ------------------------ | ------------------------------ | ------------------------------------ |
| `Accepted`               | 扣除确认接受的数量，可继续调度 | 保持当前模式与目标                   |
| `TemporarilyUnavailable` | 停止本次目标尝试并退避         | 保留目标，稍后重试                   |
| `TargetMissing`          | 结束网络输出                   | 清除已失效目标并回到被动模式         |
| `InvalidTarget`          | 按目标失效处理                 | 清除目标并回到被动模式               |
| `OutcomeUnknown`         | 停止继续输出                   | 保留目标并持久暂停，等待玩家明确恢复 |

只有 `Accepted` 能够导致输出源扣账。执行阶段抛出异常且外部结果无法证明时必须归类为 `OutcomeUnknown`，避免重复写入。

## 目标引用

持久化网络目标由 provider ID 与 provider 自有载荷组成。目标只保存重新发现网络所需的稳定信息，不保存运行时网络对象。

| 阶段 | 责任                                                        |
| ---- | ----------------------------------------------------------- |
| 创建 | provider 从玩家选择或第三方交互生成目标引用                 |
| 校验 | 公共路由确认 provider 与资源类型可用，provider 校验载荷结构 |
| 解析 | 每次输出根据当前世界和第三方状态重新定位目标                |
| 显示 | provider 提供本地化名称与紧凑目标说明                       |
| 恢复 | 玩家重新选择同一目标可以解除结果未知暂停                    |

可选模组暂时缺失不应破坏已保存目标；provider 恢复后可以继续解析。

## 配置卡

配置卡保存完整 IO 配置，也可作为第三方网络的绑定载体。

| 操作         | 语义                                             |
| ------------ | ------------------------------------------------ |
| 卡应用到机器 | 用卡配置替换机器设置，不改变机器内容             |
| 机器复制到卡 | 用机器当前设置替换卡配置                         |
| 放置时播种   | 只有当前配置来源唯一明确时才自动应用             |
| UI 选择网络  | 手持目标优先；背包中只有一个不同目标时可自动选择 |
| 多张同目标卡 | 视为同一选择                                     |
| 多个不同目标 | 要求玩家明确手持或重新选择                       |

离线目标可以被配置。可用性在实际输出时判断，不在配置阶段加载区块或强制连接网络。

## Provider 差异

| Provider          | 稳定目标             | 资源适配                | 特殊语义                                        |
| ----------------- | -------------------- | ----------------------- | ----------------------------------------------- |
| AE2               | 接入点所在维度与位置 | 物品、流体              | 每次输出跟随接入点当前所属 Grid，不加载目标区块 |
| Applied Flux      | 复用 AE2 目标        | FE 对应的 AE key        | 作为 AE 存储适配扩展，不建立独立目标模型        |
| Beyond Dimensions | 第三方网络标识       | provider 支持的资源种类 | 第三方返回值统一映射到公共结果语义              |

第三方 API 类型与转换逻辑只属于对应 Integration 模块。

## 测试边界

| 应验证                                     | 不固定                         |
| ------------------------------------------ | ------------------------------ |
| 部分接受、退避、目标丢失与未知结果状态转换 | 第三方实现源码中的具体调用文本 |
| 目标选择的唯一性与歧义处理                 | provider ID 全集               |
| 可选 provider 缺失与恢复                   | 序列化 JSON/NBT 原文           |
| 数量钳制、模拟无副作用和不加载区块         | 玩家文案原文                   |
