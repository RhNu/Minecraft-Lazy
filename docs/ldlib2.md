# LDLib2 实现要点

本页记录 Lazy 使用 LDLib2 时必须共同遵守、且难以从单个菜单还原的约束。依赖版本仍以版本目录为事实源，具体 API 以项目已解析源码和 [LDLib2 上游源码](https://github.com/Low-Drag-MC/LDLib2) 为准。

## 两侧与事件

LDLib2 的固定 UI 会在客户端和服务端分别创建。公共构造代码必须生成一致的元素树；客户端只负责即时显示，世界状态只由服务端修改。

| 场景 | 使用方式 | 约束 |
| --- | --- | --- |
| 打开、关闭、聚焦二级窗口 | `onClick` | 只改本地 UI 状态 |
| 修改方块、玩家或存档 | `onServerClick` / server event | 服务端重新校验目标、权限和当前状态 |
| 展示服务端事实 | S2C binding | 客户端不从本地世界对象补算 |
| 文本编辑并提交 | 双向 binding | 服务端仍校验最终字符串 |

不要让同一个回调同时承担客户端视觉动作和服务端业务动作。一个按钮同时需要两者时，分别注册两个回调。

## 布局状态

| API | 布局占位 | 适用场景 |
| --- | --- | --- |
| `setVisible(false)` | 保留 | 固定布局中暂时不绘制 |
| `setDisplay(false)` | 移除 | 隐藏后需要收紧布局的区域 |
| `setActive(false)` | 保留 | 操作暂不可用，但位置应稳定 |

列表分页时优先构造固定数量的行并通过 binding 控制 `display`。已知最大行数较小时不再套 `ScrollerView`；滚动容器会同时计算内容尺寸和横纵滚动条，子项宽度稍有越界就会出现无意义的横向滚动。

LSS 中的固定高度要把内容、间距、内边距一并计入。Kotlin 直接调用 LDLib2/Taffy 的布局方法时，浮点参数使用 `0f` 等明确类型，避免 Java 重载解析歧义。

## 模态窗口

项目内二级窗口统一通过 `core/ui/LazyModalDialog.kt` 创建和开关。

LDLib2 `Dialog` 默认包含一个固定宽度的 `overlay`，以及标题、内容和按钮三个自带背景的容器。若自定义内容自身已经绘制完整面板，直接 `addContent` 会叠出第二层背景；内容比默认 overlay 宽时，底层背景还会显得更窄并向下错位。

统一封装保持以下不变量：

- overlay 宽度跟随内容；
- 自带标题栏和按钮栏不参与布局；
- 自带内容容器透明、无内边距和间距；
- 自定义内容只绘制一层完整面板；
- 打开时禁止页面响应 Esc 与物品栏键，仅由弹窗捕获 Esc；文本框聚焦时物品栏键仍作为普通字符输入；
- 多个窗口按 `zIndex` 明确层级。

预先挂到根元素、再切换 `display` 的窗口不要调用 `Dialog.show`；该方法会根据默认容器的子项重新切换标题栏、内容栏和按钮栏显示状态。

## 样式与组件

- `UI.of` 先加载 `StylesheetManager.MC`，再加载菜单自身 LSS；菜单样式负责覆盖通用 Minecraft 皮肤。
- 玩家可见文字使用翻译组件，图标按钮也必须提供本地化 tooltip。
- 页面标题是根面板的第一个元素并左对齐；物品栏分区标题不等同于页面标题。
- `TextField` 的 placeholder 在 DSL spec 中设置；输入值用 binding 同步，不直接从客户端玩家对象推导服务端状态。
- 动态行、弹窗和隐藏 binding 也属于元素树，必须在两侧以相同顺序创建。

## 验证

UI 变更至少检查：

1. 目标模块能以当前 LDLib2 依赖编译；
2. `ktlintCheck` 与项目 `check` 通过；
3. 客户端分别检查 GUI 缩放、两种语言、空列表与长名称；
4. 二级窗口检查背景只绘制一层、焦点正确、Esc 能返回原菜单，聚焦文本框时 E 能正常输入；
5. 服务端操作在目标消失、权限变化和按钮状态过期时仍会拒绝无效请求。
