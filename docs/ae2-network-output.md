# AE2 网络输出设计

## 绑定模型

`配置卡`（`lazy:configuration_card`）是不可堆叠的通用 IO 模板，也是 AE2 的链接令牌。玩家使用 AE2 无线接入点的原生链接槽把卡绑定到一个接入点时，卡会切换到网络输出模式并保存该目标；再次链接会覆盖卡自身目标，但不会改动已经配置的机器。同一张卡可以配置任意数量机器，机器只保存接入点的维度和方块坐标，不保存卡身份、Grid 对象或网络 ID。

对空气右键可直接打开卡自身的 IO 界面。玩家物品栏或 Curios 配置卡栏中只有一份明确配置时，新放置的默认状态 IO 机器会复制这份配置；空白卡不参与判定，若多张卡的配置不同则不会猜测要使用哪张卡；机器自带配置（拆掉后重新放置）时保留自身配置，不被卡覆盖。

手持已链接卡右击支持网络输出的 Lazy 机器会直接应用整张卡的配置，包括 AE 目标；潜行右击则把机器当前配置复制回卡上。I/O 面板选择 AE 时依次检查主手、副手和背包：手中的已链接卡优先；背包只有一个不同坐标时自动选择；多张同坐标卡视为同一目标；存在多个不同坐标时要求玩家手持目标卡。目标当前离线也允许配置。

## 运行语义

机器每次输出时按保存坐标查找服务端世界，但不会加载区块。区块未加载、接入点缺失或不活动、Grid 尚不可用，以及当前缺少 Payload 适配器，都作为暂时不可用处理：保留目标并在 20 tick 后重试。接入点换接网络、Grid 拆分或合并后，下一次成功解析自然跟随接入点当前所属 Grid。

物品和流体分别转换为 `AEItemKey` 与 `AEFluidKey`，以无线接入点构造 `IActionSource.ofMachine`，调用当前 Grid 的 `IStorageService.inventory.insert`。Applied Flux 存在时，FE 转换为 `FluxKey.of(EnergyType.FE)` 并经过相同库存入口；不得调用 `IEnergyService.injectPower`。实际提交抛出异常时结果不可确认，机器持久暂停到玩家重新选择目标，以免重复写入。

## 可选依赖边界

AE2 类型只允许出现在 `integration.ae2`，Applied Flux 类型只允许出现在 `integration.appflux`。集成管理器先初始化 AE2，再初始化 Applied Flux；后者向 AE 的 Payload 适配器注册表动态增加 `neoforge:energy`。移除任一可选模组都不会在存档归一化时删除已有网络模式或目标，能力恢复后可继续输出。
